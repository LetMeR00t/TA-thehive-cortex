# Release Notes - v4.2.0: "The Honeycomb Patch" 🐝

## Summary
Version 4.2.0 is a **stability and reliability release**. It hardens the alert
actions and adaptive responses (alert/case creation), fixes several observable
parsing edge cases that could silently drop data or get the whole payload
rejected by TheHive, and corrects date/timestamp handling in TTP processing and
the Cases LIST search command. No new feature is introduced and no configuration
change is required — this is a safe, drop-in update from v4.1.0.

## Improvements & Bug Fixes

### 🧩 Alert Actions: robust observable parsing
- **Valid observable sub-field types**: observable sub-fields are now read with
  their documented `snake_case` names (`<field>:is_ioc`, `<field>:sighted`,
  `<field>:sighted_at`, `<field>:ignore_similarity`) and coerced to the native
  types TheHive expects. Previously the boolean `sighted` value was forwarded as
  the raw string `"1"`, causing TheHive to reject the request with
  `BadRequest - Invalid json` and silently dropping `is_ioc`, `sighted_at` and
  `ignore_similarity`. The sighting timestamp now also accepts float epoch
  values and is normalized to milliseconds.
- **Multi-value observable splitting**: fixed a regex that split observable
  values on the literal letter `n` instead of a newline, which mangled
  multi-value observables.
- **Resilient row handling**: improved handling of sanitized rows to avoid
  `KeyError` exceptions on incomplete events, and corrected the `sourceRef`
  variable used in debug logging.

### 📎 Alert Actions: reliable result attachments
- Result attachments (`attach_results`) now use a **uniquely-named temporary
  directory per invocation** instead of a fixed file name in the shared system
  temp directory. On Windows (where `splunkd` runs as the SYSTEM service and the
  temp directory is `C:\WINDOWS\TEMP`), the previous behavior caused concurrent
  or overlapping runs to collide on the same path, raising
  `Permission denied` / `No such file or directory` and **preventing the second
  alert/case of a multi-result search from being created** (e.g. UC2 — "Saved
  search, several alerts"). Temp files are now always cleaned up, and the
  attachment result is guarded against `None`.

### ⏱️ TTP & timestamp handling
- `_time` is now parsed as a **float** when processing TTPs, preventing failures
  on sub-second timestamps.
- When the configured `timestamp_field` is missing from an event, processing now
  **falls back to the current time** instead of failing.

### 🔎 Search commands
- **Cases LIST respects Date settings (#126)**: the Cases LIST action now
  correctly applies the configured date range instead of ignoring it.

## Deployment Notes
- **Prerequisite**: Python 3.9 (matches Splunk's bundled interpreter).
- **Migration Path**:
    - **From v4.1.0 / v4.0.0**: non-breaking update. Existing configuration,
      accounts, instances and certificates are preserved.
    - **From v3.9.0 (Direct Upgrade)**: you can upgrade directly to v4.2.0.
    - **⚠️ CRITICAL**: if upgrading from v3.x, the
      **[v4.0.0 migration instructions](./v4.0.0.md) are mandatory** and remain
      valid for this version (UCC architecture migration, breaking configuration
      changes, and new credential storage). Please read them carefully before
      proceeding.
- **Upgrade tip (Windows / on-prem)**: never delete the app's `local/` folder.
  Stop Splunk, back up `local/`, deploy the new build, restore `local/`, then
  start Splunk.
