# v5.2.0 - "Don't Bee Repetitive" 🐝

Splunk stops re-sending alerts TheHive already holds, and the add-on stops
retrying them. No input needs a change when you upgrade.

## Compatibility

| | Minimum | Tested with |
| :--- | :--- | :--- |
| TheHive | 5.2.0 | 5.x |
| Cortex | 3.0.0 | 4.2.0 (5.0.0 and 5.1.0) |
| Splunk | 9.3 (Python 3.9 or 3.13) | Enterprise 10.6.1 + ES 8.4.0 |

Compatible with Splunk Enterprise 10.4 to 10.6.

## New

- **Notable status once sent** (alert action *Create a new alert*, optional
  `notable_status`): once TheHive holds the alert, the Splunk ES notable is set
  to this review status ID so it is not picked up again. Empty by default; ES
  mode only; the Splunk user needs `edit_notable_events`.

## Fixed

- An alert TheHive already holds ("already exists" or HTTP 409) is no longer
  retried `thehive_creation_max_retry + 1` times: the add-on stops at once and
  logs INFO `THCA-122`. A bare 400 stays a failure.

## Upgrading

- AppInspect: no failure and no error. One `check_for_custom_mako_templates`
  warning remains on `appserver/templates/base.html`, generated by the UCC
  framework.
