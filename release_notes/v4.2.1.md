# Release Notes - v4.2.1: "The Honey Keeper" 🍯

## Summary
Version 4.2.1 is a **hotfix release** addressing a data-loss regression
introduced in v4.1.0: the `thehive_datatypes.csv` lookup could be periodically
**overwritten with default values**, wiping out user-defined custom field
mappings and causing observables to go missing from TheHive alerts and cases.
No new feature is introduced and no configuration change is required — this is
a safe, drop-in update from v4.2.0.

## Improvements & Bug Fixes

### 🗂️ Alert Actions: custom datatype mappings are no longer lost
- **Root cause**: since v4.1.0, alert actions refresh the
  `thehive_datatypes.csv` lookup from the TheHive API whenever the file is
  older than 24 hours. The refresh rebuilt the file **from scratch** with only
  the native observable types returned by TheHive, silently destroying every
  custom row (e.g. `src_ip → ip`, `dest_domain → domain`) that detections rely
  on to map Splunk fields to observables. In practice the lookup was reset
  every 24-72 hours, depending on when the next alert action fired.
- **Fix — non-destructive merge**: the periodic refresh is kept (it still
  picks up new observable types created in TheHive), but it now **preserves
  every existing row** of the lookup, custom mappings included. Only datatypes
  not already listed are appended. A full regeneration never happens once the
  file exists.
- **Atomic writes**: the lookup is now written to a uniquely-named temporary
  file and moved into place atomically, so a crash or two concurrent alert
  actions can no longer leave a truncated or half-written lookup behind.
- **Safety guard**: if the existing lookup cannot be read (locked, malformed
  encoding, permissions), the refresh is **aborted** instead of overwriting
  content that could not be preserved (logged as `THC-4`).

### 🧹 Minor
- Fixed a file-handle leak in the datatype lookup reader (the file was opened
  on every alert action run but never closed).

## Deployment Notes
- **Prerequisite**: Python 3.9 (matches Splunk's bundled interpreter).
- **After upgrading**: if your custom `thehive_datatypes.csv` was recently
  reset, restore it once from your backup — it will no longer be overwritten.
- **Migration Path**:
    - **From v4.2.0 / v4.1.0 / v4.0.0**: non-breaking update. Existing
      configuration, accounts, instances and certificates are preserved.
    - **From v3.9.0 (Direct Upgrade)**: you can upgrade directly to v4.2.1.
    - **⚠️ CRITICAL**: if upgrading from v3.x, the
      **[v4.0.0 migration instructions](./v4.0.0.md) are mandatory** and remain
      valid for this version (UCC architecture migration, breaking configuration
      changes, and new credential storage). Please read them carefully before
      proceeding.
- **Upgrade tip (Windows / on-prem)**: never delete the app's `local/` folder.
  Stop Splunk, back up `local/`, deploy the new build, restore `local/`, then
  start Splunk.
