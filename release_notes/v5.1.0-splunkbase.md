# v5.1.0

Live inputs stop losing time, and four bugs found in production are fixed.
No input needs a change when you upgrade.

## Compatibility

| | Minimum | Tested with |
| :--- | :--- | :--- |
| TheHive | 5.2.0 | 5.8.1 |
| Cortex | 3.0.0 | 4.2.0 |
| Splunk | 9.3 (Python 3.9 or 3.13) | Enterprise 10.2.1 |

## New

- **Inputs continue where they stopped.** Until now each run asked TheHive for
  exactly the last interval and kept no state: a run that failed, hung or was
  skipped lost its window for good. Each pull now remembers the end of the last
  window it collected completely, in the KV store, and the next run continues
  from there. A TheHive outage of a few minutes is caught up by the next run,
  with no gap.
- **Search head cluster:** only the captain collects; the others log `SKIP`.
- **KV store disabled** (some heavy forwarders): the watermark is kept in the
  input's checkpoint directory on that instance, with a `KV` warning.
- Two optional settings on the alerts & cases, audit, observables, tasks and
  timeline inputs: **lag_seconds** (default 60) and **max_catchup_seconds**
  (default 21600).

## Fixed

- A collected object without `_createdAt` or `_updatedAt` no longer drops the
  whole run: it is indexed with the best date available, and `TH127` names the
  missing field.
- A Splunk ES finding that annotates several techniques now gives one TTP per
  technique, instead of one procedure TheHive rejected.
- A multivalue `ttp` field gives one TTP per value.
- TheHive unreachable fails fast: connecting has its own 10 s timeout, and a
  request that timed out while reading is no longer sent again, so an alert can
  no longer be created twice.

## Upgrading

- The first run after the upgrade creates the KV collection
  `thehive_cortex_checkpoints`; the add-on's role needs write access to it
  (`admin` and `sc_admin`, as in `default.meta`).
- Events collected up to the upgrade are not collected again.
- AppInspect: no failure and no error. One `check_for_custom_mako_templates`
  notice remains on `appserver/templates/base.html`, a file generated by the UCC
  framework.
